# F_6B94 -- write_file_far(name, far buf, long len) -- NOT MATCHED (inline asm)

cs [0x6994,0x6a1e) / file [0x6b94,0x6c1e), 138 bytes.

Creates `name` (INT 21h AH=3Ch, CX=0), writes the far buffer in 32 KB chunks
(AH=40h, CX=8000h, DS = buffer segment, segment += 0x800) while the remaining
long length is >= 0x8000, writes the remainder, closes (AH=3Eh). Caller:
F_69FB (demo save).

The C part is the locals setup (`[bp-4] = FP_OFF(buf)`, `[bp-6] = FP_SEG(buf)`,
`[bp-8] = [bp-0xa] = 0`) and the long arithmetic on the `len` parameter
(`sub [bp+0xa],0x8000; sbb [bp+0xc],0` and the unsigned long compare, which do
look compiler-generated: `len -= 0x8000` / `while (len >= 0x8000)`). But the
file I/O is inline asm: `jb` on the carry flag right after `int 21h` jumping
to the close, `push ds; mov ds,ax; ...; pop ds`. A pseudo-register
reconstruction (`_DS = seg; geninterrupt(0x21);`) cannot produce the
`jb`-after-int or the DS save/restore, so this function needs `asm`.

Blocked: inline asm is forbidden here and the toolchain has no TASM.EXE.
