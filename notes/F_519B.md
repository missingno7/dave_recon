## Blocker 1 (tool limitation): far data segments

The function stores two far pointers whose segment words are MZ-relocated
(relocation sites lm 0x4FDD and 0x4FEF):

    mov word [0x137a], 0      ; g_sound_data = 1C2E:0000  (PC-speaker sounds)
    mov word [0x137c], 0x1c2e
    mov word [0x57a4], 0      ; g_demo_data  = 0B31:0000  (demo recordings)
    mov word [0x57a6], 0x0b31

In C this is `D_137A = S_1C2E;` with `extern char far S_1C2E[];` -- an
offset16 + base16 fixup pair to an external that lives in its own far
segment. `tools/symbols.py` / `match_function.link()` only know `_TEXT`
(para 0) and `DGROUP` (para 0x254D), so these 4 fixups stay unresolved.
Needed: a way to name far segments, e.g. symbols `_S_XXXX` -> (para 0xXXXX,
offset 0), with base16 fixups checked against the MZ relocation table as
for DGROUP. Writing the literal `0x1c2e` would match bytes but drop the
relocation, so I did not do that.

## Blocker 2 (4 bytes): near->far conversion of the local `def`

    original                     candidate (F_6B94(D_00AE, def, 45L))
    lea ax,[bp-0x2e]             push ss
    push ds                      lea ax,[bp-0x2e]
    push ax                      push ax

The original converts the address of the stack array to far with DS
(SS == DS in small model), with the offset computed first. Things tried
(all with `void F_6B94(char *, void far *, long)` prototype):
`def`, `&def[0]`, `def + 0`, `&def`, `(char *)def`, `(void *)def`,
`(char *)&def`, `(char near *)def`, `(char huge *)def`,
`(char _ds *)def`, `(char *)(char *)def`, `(char *)(def + 1) - 1`
-> `push ss; lea; push`.
`MK_FP(_DS, def)`, `(char *)(unsigned)def`, `(char *)(int)def`, `(0, def)`,
`(char _seg *)_DS + (char near *)def` (both orders)
-> `push ds; lea; push` (right segment, wrong order).
`(char far *)(unsigned)def` / `(int)def` -> integer-to-far (`push dx`).
Not yet tried: an unprototyped (K&R) call, different struct/array
shapes for `def`, other compiler flags.
