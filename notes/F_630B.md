# F_630B -- keyboard_isr (INT 9 handler) -- NOT MATCHED (needs inline asm)

cs [0x610b,0x6188) / file [0x630b,0x6388), 125 bytes, `void interrupt`.

## What it does
Reads the scan code from port 60h; on a break code (> 0x7F) clears
`D_8A32[key - 0x80]`, on a make code sets `D_8A32[key] = 1` and empties the
BIOS keyboard buffer (0040:001C = 0040:001A); then chains to the old INT 9
handler (`D_131A`, saved by F_6293) and sends EOI (`outport(0x20, 0x20)`).

## Best attempt (everything matches except the chain call)

```c
/* @flags -G -r- */
#include <dos.h>

extern int D_8A32[];
extern void interrupt (far *D_131A)();

void interrupt F_630B(void)
{
    int key;

    key = inportb(0x60);
    if (key > 0x7f)
        D_8A32[key - 0x80] = 0;
    else {
        D_8A32[key] = 1;
        poke(0x40, 0x1c, peek(0x40, 0x1a));
    }
    (*D_131A)();
    outport(0x20, 0x20);
}
```

Remaining diff (from +0x50): the original wraps the chain call in explicit
register saves that TC does not generate for `(*old)()`:

```
original                         candidate
615b push ax                     615b pushf
615c push bx                     615c lcall [0x131a]
615d push cx                     6160 mov ax,0x20 ...
615e push dx
615f push si
6160 push di
6161 push bp
6162 pushf
6163 lcall [0x131a]
6167 pop bp / pop di / pop si / pop dx / pop cx / pop bx / pop ax
616e mov ax,0x20 ...
```

Everything before (prologue `mov bp,DGROUP`, locals, the key-table update and
BIOS buffer flush) and after (EOI, interrupt epilogue) is byte-identical.

## Why it is blocked
* `push`/`pop` of AX..BP around the call cannot come from C: TC emits only
  `pushf; call far [ptr]` for an interrupt-pointer call. Tried: `D_131A()`,
  `(void)` / C++ `(...)` prototypes (-P), `_saveregs` on the pointer type and
  on the handler, the 9-register interrupt parameter list on the handler,
  passing pseudo-registers as arguments `(*old)(_BP,...,_AX)` (TC pushes
  interrupt-call arguments left to right and never pops them), flags
  -O -Z -k -K -a -2 -y -v -p.
* The source almost certainly had `asm push ax` ... `asm pop ax` around
  `(*oldint9)()`. That is also consistent with `key` living on the stack
  ([bp-2]): with the default -r, TC auto-allocates it to SI unless the
  function contains inline asm (reproduced here with `-r-`).
* Inline asm is forbidden for this project, and the toolchain has no TASM.EXE,
  so the matcher could not compile it anyway.

## Tool issue found
The `mov bp, DGROUP` in the interrupt prologue is a base16 fixup to segment
`_DATA`. Without a `/* @seg _DATA ... */` directive it is UNRESOLVED; with the
directive, `match_function.py` crashes (`omf.MatchError: the object has no
segment '_DATA'`) because `mod.segment_bytes("_DATA")` raises when the module
has a _DATA SEGDEF but no data. A module with an empty _DATA should be allowed
to name its _DATA base (or the base16 fixup to _DATA/DGROUP should resolve to
DGROUP's paragraph 0x254D without a directive).
