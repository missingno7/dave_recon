What it does: per video mode (D_8B32: 1 CGA, 2 EGA, 3 VGA) it calls F_6099
with a far pointer into a far data segment linked into the EXE, then
- CGA/VGA: decompresses (F_7E00) a blob linked into the EXE into the graphics
  buffer `D_56F0` (far pointer). The blob's first dword is the length; it is
  walked through a `char huge *` (N_PADD@ for `p + 4`).
- EGA: loads "EGADAVE.DAV" from disk into `D_56F0` (F_6ADE).
Finally `D_4F86 = D_8B32 - 1` (graphics index 0/1/2).

## Why it cannot be EXACT yet

The five far references are to segments OUTSIDE DGROUP and _TEXT, visible as
MZ relocations whose patched value is the segment paragraph:

| operand cs | relocated value (paragraph) | use |
|---|---|---|
| 0x1149 | 0x1D58 | F_6099 arg (CGA) |
| 0x115E | 0x0C42 | CGA compressed graphics blob |
| 0x118E | 0x1E84 | F_6099 arg (EGA) |
| 0x11B3 | 0x20CC | F_6099 arg (VGA) |
| 0x11C8 | 0x11EF | VGA compressed graphics blob |

(Also 0x1C2E / 0x0B31 at cs 0x4FDD / 0x4FEF, outside my range.)

`tools/symbols.py` only knows _TEXT (para 0) and DGROUP (para 0x254D) names,
so an `extern char far X[]` resolves either nowhere (UNRESOLVED) or, if
named `D_XXXX`, to DGROUP (wrong paragraph). The candidate uses names
`FAR_1D58`, `FAR_0C42`, ... so it reports UNRESOLVED rather than lying.

Needed tool support (suggestion): a placeholder `_FAR_PPPP` (or curated
entries) resolving to paragraph 0xPPPP offset 0 for base16 fixups and offset
0 for offset16 fixups; the existing MZ-relocation check then verifies it.
Once that exists, move `notes/blocked/F_1321.c` to `src/game/`.
